# Gazebo 시뮬레이션 + 관리자 콘솔 · 설계안

> `dummy_source.py`(시간표 기반 하드코딩)를 Gazebo Classic 11 물리 시뮬레이션으로 대체하고,
> 관리자가 웹에서 로봇을 텔레옵 조종하며 시나리오를 트리거할 수 있는 `/admin` 콘솔을 추가한다.
> 작성 2026-07-26. 상위 문서: `설계안_행복이_듀얼모드.md` §10~11.

---

## 0. 배경 — 왜 이 문서가 따로 필요한가

`설계안_행복이_듀얼모드.md`는 로봇이 **미리 짜둔 스크립트**대로 도킹하고, 액터가 **정해진 시간표**대로 낙상하는 것을 전제로 했다(§10). 브레인스토밍 도중 요구사항이 바뀌었다:

- 로봇 이동은 스크립트가 아니라 **관리자가 웹에서 텔레옵으로 직접 조종**
- 실내/실외 시나리오(낙상·자율추종·기타)는 **관리자가 버튼으로 트리거**
- 관리자가 뭘 보면서 조종할지, 로봇 원격측정을 어떻게 노출할지 등 **상위 문서에 없던 결정**이 다수 필요

따라서 상위 문서의 §10~11(Gazebo 시뮬레이션, Gazebo↔웹앱 통신)을 이 문서가 **대체**한다. 나머지 절(§1~9, §12~13: 듀얼모드 개념·판단 레이어·데이터 전략·UI 원칙)은 그대로 유효하다.

## 1. 범위

**포함**
- Gazebo Classic 11 원룸 월드(벽·가구 placeholder + 충전 스테이션 + 행복이 로봇 URDF + Human Actor)
- 관리자 콘솔(`/admin`, 기존 `web/` SPA에 라우트 추가) — 텔레옵 + 시나리오 트리거 + 카메라 뷰 + 최소 HUD
- 로봇 카메라 → `web_video_server` → 관리자 콘솔 실시간 스트림
- 도킹 거리 기반 자동 모드 전환(실외⇄실내), 디바운스 포함
- `gazebo_source.py`: `dummy_source.py`를 대체하는 rclpy 브릿지, 기존 `contracts.py` 스키마 최대한 재사용
- 신규 스키마 `RobotTelemetry` 1개(관리자 콘솔 HUD 전용)

**제외 (다음 단계로 명시적으로 미룸)**
- micro-Doppler CNN 낙상 모델, 레이더 신호 합성(§10 "경로2 고급")
- 생체(호흡·심박) 실제 추정 — 규칙 기반 더미 값 유지
- 고독사 상태머신
- Nav2 자율주행 — "자율추종 모드" 버튼은 액터 좌표로 향하는 단순 P-제어 추격으로 대역
- 다중 관리자 동시 조종(동시성 제어) — 단일 운영자 데모 전제

## 2. 아키텍처 개요

```
[관리자 콘솔 /admin] ── WebSocket ──▶ [FastAPI 백엔드] ── rclpy 브릿지(백그라운드 스레드) ──▶ [Gazebo Classic 월드]
     │  텔레옵 { linear, angular }  (홀드 입력 중 주기 전송, 데드맨 스위치)                     │
     │  시나리오 { scenario: "fall" | "follow" | ... }  (클릭 1회)                             │
     │◀── 카메라 MJPEG (web_video_server, 직접 HTTP) ─────────────────────────────────────────┤
     │                                                                                          │
     ▼                                                                                          ▼
[EventBus] ◀── gazebo_source.py 구독 ◀── ground-truth 토픽(로봇 pose, 도킹거리, 액터 pose) ── [WorldPlugin]
     │                                                                                    액터는 actor_cmd 구독,
     ▼                                                                                    idle/walk/sit/lie/fall/
[/ws WebSocket] ──▶ 키오스크 · 대시보드 · 관리자 콘솔(상태배지)                              recover 트리거 전환
```

핵심 불변식: **로봇 위치·속도·도킹거리는 항상 Gazebo 물리에서 나온 실측값**이고, **액터의 활동 종류(걷기/낙상/정지 등)는 관리자가 고른 시나리오 라벨**이다. 이 둘이 결합해 기존 `PersonState`가 만들어진다 — 값의 출처만 바뀌고 소비자(키오스크·대시보드)는 무변경.

## 3. Gazebo 월드 & 모델

- **월드**: `sim/worlds/happy_care_room.world` — 벽·바닥·가구는 단순 박스 프리미티브. 충전 스테이션은 색으로 구분되는 고정 링크.
- **로봇**: `sim/models/haengbogi/` — 디퍼렌셜 드라이브 URDF(차체+구동바퀴 2+캐스터), 전방에 카메라 링크. 실제 보행기 외형 재현은 이번 스코프 아님(프리미티브로 충분).
- **Human Actor**: 스켈레톤 애니메이션(walk.dae) 대신 **강체 모델 + WorldPlugin이 매 스텝 pose를 보간**하는 방식 채택 — idle(직립)·sit·lie·fall(직립→바닥 눕는 자세로 회전+하강 보간)·recover 전환을 커맨드로 트리거. 관절 애니메이션보다 시각 품질은 낮지만, 리깅된 액터 에셋 없이 이번 스코프 내에서 구현 가능.
- **WorldPlugin** (C++, `sim/plugins/`): 두 가지 책임만 가진다 — ① 매 스텝 ground-truth 퍼블리시(로봇 pose, 로봇↔스테이션 거리, 액터 pose/velocity), ② `actor_cmd`/`robot cmd_vel` 구독해 실행. 판단 로직(활동 분류, 모드 디바운스)은 여기 넣지 않는다 — Python 쪽(`gazebo_source.py`)의 책임.

---

## 4. 로봇 텔레옵

- 전송: **WebSocket**(REST 폴링 대비 지연 적음, 홀드 입력에 적합)
- 관리자 콘솔 UI: 방향키 버튼(상하좌우) + 속도 슬라이더, **WASD 키보드 리스너 병행**
- 백엔드는 수신한 `{linear, angular}`를 `geometry_msgs/Twist`로 변환해 로봇의 `/cmd_vel`에 퍼블리시
- **데드맨 스위치**: WebSocket 연결 끊김·500ms 이상 명령 미수신 시 백엔드가 자동으로 정지 명령(`Twist()` 0)을 퍼블리시. 브라우저 탭 이탈/새로고침 시 로봇이 계속 움직이는 사고 방지.
- **자율추종 모드**와의 관계: 자율추종 버튼이 활성화된 동안은 텔레옵 입력을 무시(서버 사이드에서 우선순위 중재) — 버튼을 다시 누르거나 임의 텔레옵 입력이 들어오면 자율추종 해제.

---

## 5. 도킹 감지 & 모드 전환

- WorldPlugin이 매 스텝 로봇↔스테이션 유클리드 거리를 퍼블리시
- `gazebo_source.py`가 거리 < 0.3m을 1초 연속 확인(디바운스) → `SystemMode.INDOOR` 전환, `CareEvent(type="mode_change")` 발행
- 반대 방향(거리 초과 지속)도 동일 1초 디바운스로 `SystemMode.OUTDOOR` 복귀
- 관리자 콘솔의 시나리오 버튼 세트는 **백엔드가 확정한 현재 모드**(단순 프론트 좌표 추정이 아님)를 기준으로 전환 — 도킹 애매한 경계에서 잘못된 시나리오 트리거 방지

---

## 6. 시나리오 트리거

관리자 콘솔에서 현재 모드에 따라 버튼 세트가 바뀐다:

| 모드 | 버튼 | 동작 |
|---|---|---|
| 실외 | 낙상(IMU) | 로봇 자체의 IMU 낙상 감지 대역 — `CareEvent(type="fall", mode=outdoor)` 발행 |
| 실외 | 자율추종 모드 | 로봇이 액터 좌표로 단순 P-제어 추격(텔레옵 우선순위 낮춤, §4) |
| 실외 | 기타 | 향후 시나리오용 자리표시자 — 정보성 `CareEvent(severity="info")` 1건만 발행 |
| 실내 | 낙상(레이더) | 액터에 `actor_cmd=fall` 전송 → WorldPlugin이 포즈 보간 시작 → `gazebo_source.py`가 활동 전환 감지해 `CareEvent(type="fall")` 발행 |
| 실내 | 정상 활동 | `actor_cmd=idle/sit` 순환 재생 |
| 실내 | 장시간 무동작 | `actor_cmd=lie`로 전환 후 유지(고독사 상태머신 자체는 다음 단계 스코프) |

**리셋**: 낙상류 시나리오는 트리거 후 **5초 뒤 자동 회복**(`actor_cmd=recover` 자동 전송, `dummy_source.py`의 기존 회복 패턴과 동일). 관리자 개입 불필요 — 데모 반복이 빠름.

**상태 잠금**: 액터가 트리거된 시나리오를 재생 중일 때 새 시나리오 버튼은 비활성화(회색 처리) — 겹쳐 트리거되는 경합 방지.

## 7. 텔레옵 시각 피드백

- 로봇 URDF 카메라 링크 + `libgazebo_ros_camera.so` → `sensor_msgs/Image`
- `ros-humble-web-video-server`(apt 설치 가능, 확인됨) → MJPEG 변환
- 관리자 콘솔은 `<img src=".../stream?topic=...">`로 직접 임베드 — 로봇 1인칭 시점으로 조종
- 최소 HUD: `RobotTelemetry` 스키마(§8) 값을 화면 상단에 텍스트로 표시(도킹거리, 연결상태, 현재 모드) — 별도 미니맵/시각화는 만들지 않는다(카메라로 충분, YAGNI)

## 8. 데이터 계약 변경

`contracts.py`의 기존 `PersonState`, `CareEvent`는 **필드 변경 없음**. 아래 1개 모델만 신규 추가:

```python
class RobotTelemetry(BaseModel):
    ts: float
    pose: Tuple[float, float, float]   # x, y, yaw
    dock_distance: float
    mode: SystemMode
    teleop_connected: bool
```

envelope kind `"robot_telemetry"`로 버스에 흘려보낸다. 키오스크·대시보드는 기존과 동일하게 `kind` 스위치에서 모르는 값은 무시 — 두 화면은 무변경.

## 9. 백엔드 통합

- `backend/happy_care/gazebo_source.py` 신설, `dummy_source.py`와 동일한 시그니처(`async def run_gazebo(bus: EventBus) -> None`)
- 내부 구조를 **순수 판단 로직**(pose→활동 매핑, 거리→모드 디바운스, RobotTelemetry 조립)과 **rclpy I/O**(구독 콜백, 스레드)로 분리 — 전자는 Gazebo 없이 pytest로 유닛테스트 가능
- rclpy 콜백(별도 스레드)에서 `bus.publish(...)`(코루틴) 호출 시 `asyncio.run_coroutine_threadsafe`로 메인 이벤트 루프에 안전하게 넘긴다 — asyncio·rclpy 스레드 경계는 이 프로젝트에서 처음 다루는 통합 지점이라 구현 초반에 스파이크로 검증
- **폴백**: ROS 2 환경이 없거나 Gazebo가 안 떠 있으면 백엔드는 기동 시 자동으로 `dummy_source.py`로 폴백(환경변수 또는 rclpy import 실패 감지) — Gazebo 셋업이 안 된 팀원도 README의 기존 `uvicorn` 한 줄로 그대로 개발 가능해야 한다.
- 오케스트레이션: `sim/launch/happy_care_sim.launch.py` 하나로 gzserver + 로봇 + 액터 + 스테이션 + `web_video_server`를 한 번에 기동

## 13. 알려진 제약 (다음 단계에서 해소)

- 액터는 관절 애니메이션이 아닌 강체 포즈 보간이라 낙상 동작이 시각적으로 뚝뚝 끊길 수 있음 — 데모 품질 이슈, 리깅된 액터 에셋 확보 시 개선
- `자율추종 모드`는 실제 AI Vision이 아니라 좌표 기반 P-제어 추격 — 실제 비전 파이프라인은 이 스코프 밖
- 다중 관리자 동시 텔레옵 미지원(단일 운영자 전제)
- micro-Doppler CNN, 생체 실측, 고독사 상태머신은 이후 단계
